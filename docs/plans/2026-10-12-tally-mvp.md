# Tally MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Tally, a local-only, expense-tracker-first web app (installable PWA): fast expense and income logging, budgets, and monthly and yearly savings goals, with optional food (barcode) and gym logging joined on one Today screen. All data lives in a SQLite database inside the user's browser.

**Architecture:** Vite + React + TypeScript single-page app, installable as a PWA and served as static files with no backend. SQLite runs in the browser via the official `@sqlite.org/sqlite-wasm` build inside a Web Worker, persisted to the Origin Private File System with the `opfs-sahpool` VFS. All domain logic lives in pure TypeScript modules under `src/domain/` that talk to SQLite through a tiny `SqlExecutor` interface, so the same SQL runs against the worker in the browser and `better-sqlite3` in Vitest. Money and savings are built first (Tasks 1–7 produce a usable expense tracker); food and training follow.

**Tech Stack:** Vite, React 18+, TypeScript strict, react-router, Tailwind CSS + shadcn/ui, vite-plugin-pwa (Workbox), @sqlite.org/sqlite-wasm, barcode-detector (BarcodeDetector ponyfill backed by zxing-wasm), Vitest + jsdom + @testing-library/react, better-sqlite3 (tests only), self-hosted fonts via @fontsource-variable (Bricolage Grotesque, Atkinson Hyperlegible Next).

**Spec:** "All-in-One Tracker App: Research Report" (claude.ai doc, 2026-10-12), sections 2, 3, 4, 6 and 8, plus these product decisions: Tally is an expense tracker first, has monthly and yearly savings goals, and is local-only with its database in the browser. Every requirement this plan depends on is copied into Global Constraints, so executors do not need the doc.

## Amendments (2026-10-13, approved after the first build)

These decisions were made during implementation and approved by the product owner. Where they conflict with the text below, they win.

- **Tables:** the schema has 19 tables (the list in Task 2), not 20.
- **Left to spend** counts only categories that have a budget for that period. With no weekly budget, Today and Money show "spent this week" with a "Set a budget" link.
- **UI stack:** Tailwind CSS v4 (CSS-first, no `tailwind.config.ts`) with Tally's own components in `src/components/ui/` instead of shadcn/ui.
- **Tokens:** adds `--on-pond` and `--on-marigold` text tokens so dark-mode buttons pass AA. Marigold tally marks are decorative and have no contrast requirement; the visible "£X to go" text carries the meaning.
- **Settings:** adds `onboardedAt` (so `backupDue` works before the first backup) and `theme` (manual light/dark choice).
- **Onboarding income:** asks which day of the month the user is paid (1–31, default 1). The monthly income rule starts on the next occurrence of that day, clamped to the month's last day. Recurring rules store `anchor_day` so monthly and yearly dates return to that day after a short month.
- **Health consent:** names "food logs and body weight" only. Workouts are not covered by consent or by "Delete health data". Turning Food on later (from More) asks for consent first, and "Delete health data" turns Food off.
- **Food seed:** the bundled 55-food list is Tally's own hand-written typical values, stored as `source = 'starter'` (not `cofid`) in `public/seed/starter.json`. Real CoFID data goes in `public/seed/cofid.json`, generated by `scripts/build-seed.ts --cofid <csv>`, and is loaded only when that file exists. Search ranks `user` > `off` > `cofid` > `starter`.
- **SqlExecutor.transaction** passes the callback a transaction-scoped executor: `transaction(fn: (tx: SqlExecutor) => Promise<void>)`. Calls on the outer executor wait until the transaction finishes.
- **Barcode decoding:** the zxing `.wasm` is served from Tally's own origin (precached), not the library's default CDN.
- **Layout and nav (2026-10-13, after screenshots):** 20 px side gutters and more vertical space between sections; the bottom nav uses icons above labels (`lucide-react`) with a round Add button at the exact centre. Workout sets are two-line rows so nothing scrolls sideways at 375 px, and the rest timer sits at the top of the workout.
- **From the whole-branch review:** budgets can be removed by clearing the field; withdrawals are capped at what's saved in the goal's current period; More's monthly income edits the recurring income rule; restore happens in place (no page reload) and is offered on the first onboarding screen; Open Food Facts lookups time out after 8 s and never cache a zero-kcal food that has real macros.
- **Profile instead of a More tab (2026-10-13):** there is no More or You tab. The bottom nav is Today · Money · (Add) · Food · Train; Add stays in the exact centre and the items split evenly around it (Food and Train only when on; with both off it is Today · (Add) · Money). The profile is the user's avatar, a 40 px circle with a 44 px touch target in the top-right of Today, labelled "Your profile and settings"; a small amber dot (and a longer label, e.g. "…, backup due") appears when a backup is due or the browser can't save data. It opens `/you` as a full screen inside the app shell (nav still visible) with Back to Today at top-left; `/more` and `/more/<screen>` redirect to `/you` and `/you/<screen>`. The profile opens with the avatar (one of 16 bundled icons on one of 5 token-based colours, each pair ≥ 4.5:1), the display name (default "You") and "Tracking since", then a progress section (Money, plus Food and Training when on; 3, 6 or 12 months), then grouped settings rows that each open their own screen. Weeks still start on Monday; there is no first-day-of-week setting. New settings: displayName, avatarIcon, avatarColour, payDay (mirrors the income rule), restSeconds, dateFormat ("12 Oct 2026" or "12/10/2026").
- **Charts:** hand-built SVG with a table view and an accessible summary. Series colours `--chart-spent` (#159A92) and `--chart-saved` (marigold in light, #C48426 in dark) were checked with the dataviz palette validator; income is a neutral dashed line on the same axis. Training uses two charts (workouts, then volume) rather than a dual axis. Food never charts calories or body weight.
- **Unverified on real devices:** see `docs/manual-testing.md`.

## Global Constraints

- **Local-only:** no backend, no accounts, no cloud sync, no analytics, ads or third-party tracking. The only network requests after the app is installed are Open Food Facts barcode lookups, and the app works fully offline otherwise (service worker precaches the app shell, WASM and seed data).
- **Database in the browser:** SQLite (`@sqlite.org/sqlite-wasm`) in a dedicated Web Worker, file `tally.sqlite3` in OPFS via `opfs-sahpool`. If OPFS is unavailable, fall back to an in-memory database and show a persistent banner: "Your data can't be saved in this browser. Use Chrome, Edge, Firefox or Safari 16.4+."
- **Protect local data:** call `navigator.storage.persist()` on first run and show the result in Settings. On iOS Safari, show an "Add Tally to your Home Screen to keep your data safe" prompt until installed (Safari may clear site data for sites not used for 7 days). Backups are export/import JSON files; nudge for a backup when `lastBackupAt` is more than 30 days old.
- **Expense tracker first:** the Money pillar is always on and cannot be disabled. Bottom nav order is Today · Money · Food · Train · More. The quick-log sheet's first and largest button is "Add expense". Food and Train are optional pillars chosen in onboarding.
- Mobile-first layout (designed at 375 px wide, usable up to desktop); bottom navigation and primary actions in the lower third of the screen.
- Money is stored as integer pence (`amount_pence INTEGER`, always positive) with `currency TEXT DEFAULT 'GBP'`; never floats. Direction comes from `transactions.kind` ∈ `expense|income`. Savings contributions may be negative (withdrawals).
- Every row has `id TEXT PRIMARY KEY` (`crypto.randomUUID()`), `created_at`, `updated_at` (ISO 8601 UTC strings) and `deleted_at` (nullable). Deletes are soft; every query filters `deleted_at IS NULL`.
- Day boundaries use the device's local date as `log_date TEXT 'YYYY-MM-DD'`. Weeks start on Monday; months are calendar months; savings years are calendar years (1 Jan – 31 Dec).
- Spending totals, budgets and "left to spend" count only `kind = 'expense'`; income never reduces spend.
- Savings goal progress bars and budget states never use red; use neutral and accent colours, and phrase shortfalls as "£X to go".
- Each food log stores a snapshot of kcal, protein_g, carbs_g, fat_g at logging time; editing or deleting a food never changes past logs.
- Open Food Facts requests add `app_name=Tally&app_version=0.1` query parameters (browsers do not allow setting `User-Agent`), and the app shows "Food data © Open Food Facts contributors, ODbL" on the food search and product screens.
- User-created foods live in `foods` with `source = 'user'`; Open Food Facts rows use `source = 'off'`, CoFID rows `source = 'cofid'`, and Tally's hand-written starter list `source = 'starter'`. Never merge user edits into `off` rows — write a new `user` row instead.
- CoFID data is CC BY-NC-SA 4.0 (non-commercial). Do not add any payment or subscription code in this plan.
- Calorie target floors: 1200 kcal (female), 1500 kcal (male/unspecified); max planned loss 1% of body weight per week. Constants live in `src/domain/safety.ts` with a comment that they must be reviewed by a registered dietitian before public launch.
- Goal weight implying BMI < 18.5, or 3+ consecutive logged days under the floor, shows a non-alarming support message mentioning Beat (beateatingdisorders.org.uk).
- No red "over target" colours for food, no "good/bad food" language. A "Hide calorie numbers" setting hides kcal everywhere in food screens and the Today card.
- Weight and body metrics are optional and never asked on the first onboarding screen.
- Onboarding order: age confirmation (18+) → optional pillars (Food, Train; Money shown as included) → monthly income and pay day (optional, skippable) → first savings goal (optional, skippable) → health-data consent only if Food was chosen (separate screen, names "food logs and body weight", must be actively ticked; declining removes Food) → "Your data stays on this device" screen explaining backups.
- Tap budgets: add an expense in ≤ 3 taps from Today, log a savings contribution in ≤ 3 taps from the goal list, log a recent food in ≤ 3 taps, complete a pre-filled set in 1 tap.
- All UI follows the "Design system and UX fundamentals" section below and uses the Task 5 components; screen tasks load the frontend-design skill before building.
- Touch targets ≥ 44×44 px; every icon-only button has `aria-label`; text sizes in `rem`; visible focus states; respect `prefers-reduced-motion` and `prefers-color-scheme`.

## Design system and UX fundamentals

Executors building any screen load the **frontend-design** skill first and follow this section; it is the design plan that skill asks for, already reviewed against generic defaults. Tally's subject is a pocket ledger for a UK twenty-something: logging a £3.40 meal deal at the till or a set between lifts, one-handed, in a few seconds. The design's job is to make the number you need obvious at a glance and logging feel instant.

### Tokens

| Token | Light | Dark | Use |
| --- | --- | --- | --- |
| `--chalk` (background) | `#F2F5F3` | `#0F1A1D` | Page background — a cool mint-white, deliberately not warm cream |
| `--surface` | `#FFFFFF` | `#172427` | Sheets, inputs, keypad |
| `--ink` (text) | `#1B2A2F` | `#E6EEEC` | Body text and amounts — a deep teal-black, not `#111` |
| `--slate` (muted text) | `#5C6B70` | `#9DB0B4` | Secondary text, captions |
| `--fog` (lines) | `#D5DDDA` | `#2A3A3E` | Dividers, input borders |
| `--pond` (primary) | `#0F6E6A` | `#3FB8AE` | Primary buttons, money accents, links, focus ring |
| `--marigold` (savings) | `#E9A23B` | `#F0B85A` | Savings tally marks and goal fills only — never text |
| `--amber-ink` | `#7A4B00` | `#F5C77A` | "Over budget" and "behind" text — the only warning colour; no red anywhere except the typed-confirmation delete dialog (`--danger: #A3261E` / `#F2867D`) |

All text pairs meet WCAG 2.2 AA (4.5:1 for body, 3:1 for large text and UI borders); Task 5 tests this. Dark mode follows `prefers-color-scheme`, with a manual override in More.

### Type

- **Bricolage Grotesque** (variable) for amounts and screen titles — characterful numerals make money the visual hero.
- **Atkinson Hyperlegible Next** for everything else — designed for legibility at a glance, which suits a gym or a till.
- Self-host both via `@fontsource-variable/*` packages (no Google Fonts CDN — Tally is offline and local-only). Amounts in lists use `font-variant-numeric: tabular-nums`; if Bricolage lacks tabular figures, use Atkinson Hyperlegible Mono for list amounts only.
- Scale (1.25 ratio, 16 px base, in rem): 0.8, 1, 1.25, 1.563, 1.953, 2.441, 3.052. The hero amount on Today is 3.052rem; screen titles 1.563rem; body 1rem, line-height 1.5; captions 0.8rem.
- Sentence case everywhere. No all-caps labels, no eyebrow labels above headings, no single accented word in a heading, no "→" on buttons.

### Layout

- Single column, left-aligned, 16 px side gutters, 8 px spacing grid, max content width 32rem centred on larger screens.
- Lists are full-width rows separated by `--fog` hairlines, not stacks of identical cards. Radius has hierarchy: sheets 20 px, buttons and inputs 12 px, list rows 0, chips fully rounded. No drop shadows except one on sheets.
- Bottom nav (64 px plus safe-area inset) with Today · Money · Food · Train · More; a wide "Add" pill in the centre opens the quick-log sheet. Primary actions sit in the bottom third.

### Signature element: tally marks

Spend the boldness in one place. Savings goals are drawn as hand-cut tally marks (groups of four upright strokes crossed by a fifth) in `--marigold`, one stroke per 5% of the target — twenty strokes is a met goal. They appear on the Today card, the goals list and goal detail, drawn as inline SVG with a slight per-stroke rotation seeded from the goal id so each goal looks hand-made but stable. Adding a contribution draws the new strokes in (250 ms, skipped under `prefers-reduced-motion`). Everything else stays quiet: no gradients, no decorative illustration, no entrance animations on page load.

### UX fundamentals

- **Speed:** the keypad opens with focus already in it; the last-used category is pre-selected; Save is reachable with the thumb. Never show a spinner for local reads — the database is local, so render immediately.
- **Feedback and undo:** every save shows a toast naming the same action ("Save expense" → "Expense saved", with Undo for 5 seconds). Deleting a row is immediate with Undo, not a confirm dialog. Only "Delete health data" and "Delete everything" use a typed confirmation.
- **Consistent vocabulary:** Spent, Left to spend, Income, Saved, To go, Goal, Budget. A button says exactly what happens ("Save expense", "Add to goal", "Log set"), never "Submit" or "OK".
- **Empty states invite action:** e.g. Money with no transactions shows "No spending yet this week" and an "Add expense" button. Errors say what happened and what to do, without apologising ("That amount isn't valid. Use numbers like 4.50.").
- **Forms:** `inputMode="decimal"` for money and weights, labels above fields (never placeholder-only), inline validation on blur, Save disabled until valid, input preserved on error.
- **Navigation:** back always returns to where the user came from; sheets close with a swipe down, the Escape key or a visible Close button.
- **Accessibility:** touch targets ≥ 44×44 px; visible 2 px `--pond` focus ring; every icon-only control has an `aria-label`; tally marks carry an accessible label ("Holiday 2026, 68% saved, £640 to go"); amounts are announced with the currency ("£3.40"); colour is never the only signal (behind-target also says "behind"); layouts hold up at 200% text zoom and 320 px width.
- **Critique before commit:** every screen task ends with screenshots at 375 px in light and dark mode, checked against this section and the frontend-design skill's restraint rules (remove one unnecessary element before committing).

## Review Focus

1. Browser storage failure or eviction — OPFS unavailable, private browsing, or storage cleared — never loses data silently: the user sees the banner, and a backup can be restored with import. (Tasks 1, 16)
2. UK money input — "4.5", "£4.50", "4,50", " 12 ", "1,250.00" all parse; "abc", "", negative and > £1,000,000 are rejected. (Task 3)
3. Savings across boundaries — a contribution on 31 Dec vs 1 Jan, or 31 Oct vs 1 Nov, counts towards the right year or month, and withdrawals never make progress negative. (Task 4)
4. Two tabs open at once — writes from one tab don't corrupt or overwrite the other; the second tab is told Tally is already open. (Task 1)
5. Barcode not in Open Food Facts, offline, blocked by CORS, or missing nutrients — user lands on a pre-filled "create food" form, never a crash or a zero-kcal food. (Task 9)

Rules:
- Period window: `month` → calendar month containing `onDate`; `year` → calendar year containing `onDate`; `once` → `startDate` (default creation date) to `targetDate`. Only contributions inside the window count.

- `expectedByNowPence = round(target × elapsedDays / totalDays)` with both counts inclusive of `onDate` and the window's first day.
- `onTrack = savedPence >= expectedByNowPence`.
- `perMonthNeededPence = ceil(remaining / monthsLeft)` where `monthsLeft = (endYear − y) × 12 + (endMonth − m) + 1`, minimum 1, using the window end.
